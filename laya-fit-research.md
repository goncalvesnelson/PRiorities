## Decision

Laya is a plausible candidate for a later measured experiment on short, prepared change descriptions. It is not an evidenced replacement for the first semantic code-classification pass. Keep the approved two-stage Anthropic implementation while collecting labelled edits that would let us test a replacement. Do not let an unvalidated Laya score determine which code disappears from the initial review.

The strongest direct warning is in Laya's own tool instructions: “Do NOT use for open Q&A, summarization, rewriting, code, or multi-hop reasoning.” Its finite-choice interface fits our label vocabulary, but that interface alone does not establish understanding of behavior changes. [Current MCP source](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya/mcp/server.py#L75-L80).

## What can be reused

The TypeScript implementation accepts caller-supplied state and finite-choice, ordinal or Boolean questions; it tokenizes the state, runs an encoder and decision head, and returns labels and probabilities. We could supply a compact edit plus before/after evidence and ask for `behavioral`, `mechanical`, `supporting`, or `uncertain`. It does not retrieve callers, compare ASTs or generate evidence explanations in this inference path. Its schema interface explicitly rejects free strings, arrays and nested objects. These are conclusions from the implementation, not a claim that code text cannot be submitted. [Prediction path](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/src/agent.ts#L421-L530), [schema subset](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/src/structured.ts#L1-L19).

No semantic-diff, PR-review or behavioral-equivalence benchmark was found by scoped searches of `benchmarks`, `research`, `laya`, `laya-ts`, `docs`, `tests` and README. The code-related examples route natural-language requests such as a request to refactor a service; they do not classify program changes. The evaluation README says its tiny fixture makes no quality claim and identifies MASSIVE English as the scheduled suite. This is a bounded search finding, not proof that no external evaluation exists. [Evaluation scope](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/research/evals/README.md#L5-L7), [scheduled suite](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/research/evals/README.md#L73-L79).

## Context and confidence

TypeScript defaults to 512 total tokens and a 192-token question/option budget, unless the checkpoint configuration overrides them. Options and instructions share the total budget with the edit. Excess string/object state is cut off at the end; arrays retain their tail. Passing a long before/after pair can therefore omit the relevant half without a classification-level failure. These are defaults, not a universal architectural limit. [Configuration](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/src/agent.ts#L297-L305), [sequence budgeting](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/src/common.ts#L75-L113).

Choice `confidence` measures entropy concentration; `answer_confidence` is the largest option probability. Neither has been validated for our edits. The repository also states that current checkpoints have no useful learned `act_probability` signal, so that field must not become a hide/show gate. Python's long-input API aggregates windows and explicitly disclaims whole-document calibration; it does not establish joint reasoning across before/after windows. [Confidence calculation](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/src/common.ts#L121-L134), [act-head limits](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/research/evals/README.md#L13-L18), [long-input contract](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya/agent.py#L1091-L1118).

## Chrome integration

Local browser inference is possible in principle, so a separate local server is not inherent to Laya. It still adds a model runtime and distribution work to the current API-key extension:

- The browser provider imports `onnxruntime-web`, loads `encoder.onnx` and `head.onnx`, and uses WebGPU/WASM. Tokenizer and configuration files are also required; the documented workflow exports the split model first. [Browser provider](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/src/providers.ts#L511-L550), [export workflow](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/README.md#L3-L40).
- Stock `Agent.load` distinguishes browser from Node by the presence of `globalThis.window`. Our MV3 background service worker has no window, so this implementation selects the Node branch there. It needs a browser page/offscreen context or an adapted loader, plus a tested lifecycle. This incompatibility follows directly from the branch; it was not tested with model inference. [Loader](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/src/agent.ts#L584-L619).
- MV3 requires packaged JavaScript/WASM; adding a remote WASM URL is not a distributable solution. The extension must enable WebAssembly in its CSP and serve the matching ONNX runtime assets locally. ONNX exposes `env.wasm.wasmPaths` for that configuration. [Chrome remote-code rule](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code), [Chrome CSP](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy), [ONNX runtime configuration](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html#envwasmwasmpaths).
- Model data needs packaging or a download/cache flow. The provider tries the network first and falls back to CacheStorage; a successful first download alone does not guarantee an offline cache, because cache writes can fail. [Fetch/cache behavior](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/src/providers.ts#L185-L245).

The pinned English checkpoint lists `model.safetensors` at **843 MB**, and does not list the required split ONNX files at its root. That is a source-checkpoint size, **not a measured browser download size**. The exporter converts the model to float32, so the 843 MB figure must not be promised as the ONNX footprint. No exported size, peak memory or Chrome latency was measured. Code and the inspected checkpoint declare Apache-2.0. [Pinned model files and licence](https://huggingface.co/convaiinnovations/laya/tree/55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851), [export dtype](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/laya-ts/scripts/export_onnx.py#L135-L147), [code licence](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/LICENSE).

## Experiment before adoption

Use the same captured edits and human labels as the two-stage review evaluation. Include mechanical changes, real behavior changes that look mechanical, and cases requiring caller context. Compare Laya against the existing classifier on false mechanical labels, uncertainty coverage, truncation, cold-start time and memory. Fit any threshold on separate labelled data. During this experiment its labels should be recorded for comparison without changing visibility.

No model weights or dependencies were downloaded, no inference accuracy test was run, and no private code was sent to Laya. The public source and model listing were inspected; an additional Hugging Face metadata API request timed out. The user's separate Laya checkout was untouched.
