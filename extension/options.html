How reviews run

Up to three files are reviewed at once, then related changes are checked together. Generated files stay out of analysis until you choose Review anyway.

Your login stays with the CLI. No API key or local repository checkout is needed.

Saved reviews

Matching reviews reopen without new model calls. The cache stores review explanations and selected code excerpts on this browser. Changes to commits, captured context, provider, model, effort or review preferences require a fresh review.

Checking saved reviews…

Default: 100 MB. When full, the least recently used reviews are removed first. You can choose 1–1024 MB.

Try it on a pull request

  1. Choose a connected CLI, save your settings, then open a GitHub PR’s Files changed tab.
  2. Choose Analyze PR in PRiorities.
  3. Read the review decisions and use GitHub's Viewed checkbox as you finish each file. Open Details for source evidence or switch back to the full GitHub diff whenever needed.

Your review checkmarks use GitHub's Viewed state. AI analysis never marks a file reviewed for you. PRiorities does not post comments or approve changes.
